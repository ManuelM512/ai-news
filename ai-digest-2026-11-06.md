## New Model

### 1. Meituan Releases LongCat-2.5 — 1.6T-Parameter Multimodal Agent Model
**Source:** [CryptoBriefing](https://cryptobriefing.com/meituan-releases-longcat-2-5-multimodal-model/) · [AI Weekly](https://aiweekly.co/alerts/meituan-ships-longcat-25-a-16t-param-multimodal-agent-model) · [RuntimeWire](https://runtimewire.com/article/meituan-longcat-2-5-native-multimodal-agentic-model)

Meituan shipped **LongCat-2.5** on November 2, 2026 — a 1.6-trillion-parameter mixture-of-experts model purpose-built for long-horizon agentic work. It processes vision and text in a unified token framework (no separate encoders), supports a 1M-token context window, and can produce outputs up to 128K tokens. Available via Meituan's chat service and API; model weights are not yet public.

**Why it matters:** A 1.6T-parameter native multimodal MoE focused on agent execution — not just text generation — raises the bar for open and commercial agent foundations. Meituan's bet on unified token-level multimodality over separate encoder stacks may shape how future agentic models handle vision-grounded tasks.

## New Agent Tool

### 2. Google Cloud Agent Compute Engine — Hardware-Isolated MicroVM per Agent
**Source:** [Virtualization Review](https://virtualizationreview.com/articles/2026/10/26/google-unveils-compute-engine-for-ai-agents.aspx) · [SDxCentral](https://www.sdxcentral.com/news/google-launches-architecture-to-ace-agentic-compute-workloads/) · [Futurum Group](https://futurumgroup.com/?p=97350)

Google Cloud announced **Agent Compute Engine** on October 22, with active coverage continuing this week. The system spins up a hardware-isolated microVM for each AI agent — using Titanium TPUs for isolation — allowing agents to run code, shell commands, and browser sessions safely. MicroVMs can pause and resume, which suits human-in-the-loop workflows. Agent Gateway enforces policy on inbound and outbound agent traffic; Agent Registry tracks approved agents and tools; Agent Identity assigns secure identities. Cross-cloud governance is listed as "in preview soon."

**Why it matters:** Moving from soft process isolation to hardware microVMs is a significant security upgrade for agent infrastructure. It directly addresses one of the core concerns in Apple's 10-K this week (see item 4): agents exceeding their permissions or escaping their sandboxes.

### 3. Akamai Launches Inference Hosting and Agent Sandbox in Beta
**Source:** [AI Agent Store — Week of Nov 3, 2026](https://aiagentstore.ai/ai-agent-news/this-week) · [Security Brief Asia](https://securitybrief.asia/story/google-cloud-launches-ai-agent-engine-governance)

Akamai entered the agent infrastructure market this week with two beta products: **Akamai Inference**, a managed model-serving layer running on its edge network, and **Akamai Agent Sandbox**, an isolated runtime for executing agent-generated code — including shell commands and file writes — without hitting the host environment.

**Why it matters:** Akamai's edge presence means lower-latency inference closer to end users globally. The Agent Sandbox addresses a real production gap: most teams running code-writing agents still lack a safe execution tier between model output and their own infrastructure.

## Research

### 6. UniRestorer++ Demonstrates Log-Linear Scaling on Universal Image Restoration
**Source:** [AI Weekly — Nov 5 Roundup](https://aiweekly.co/ai-news-today)

A new arXiv paper, **UniRestorer++**, shows log-linear PSNR improvement as model size scales from 154M to 2.9B parameters on universal image restoration tasks (denoising, deblurring, super-resolution, deraining). The result suggests that general-purpose restoration — handling arbitrary degradation types in one model — exhibits predictable scaling behavior.

**Why it matters:** Scaling laws have guided progress in language and coding; confirming they also hold for perceptual vision tasks gives practitioners a principled way to allocate compute budgets for restoration models without task-specific tuning cycles.

### 7. Paper Proposes End-of-Conversation and Single-Action Compaction for Long Agent Sessions
**Source:** [AI Weekly — Nov 5 Roundup](https://aiweekly.co/ai-news-today) · [Hugging Face Discuss](https://discuss.huggingface.co/t/preprint-on-llm-context-compaction/176090)

A new preprint introduces two targeted compaction strategies: **End-of-Conversation Compaction**, which summarizes only after a full session completes, and **Single-Action Compaction**, which compresses only the most recent completed tool-action pair. Both keep accuracy close to full-history baselines while substantially cutting token costs compared to rolling-window summarization approaches.

**Why it matters:** As agentic workflows grow to hundreds of tool calls per session, context compaction is a critical cost and reliability lever. The finding that recall in compacted zones can drop to near-zero (0–7%) even when keyword search still finds the facts (82–93%) is a sharp reminder that semantic completeness and syntactic presence are not the same thing.

### 8. Together AI Persistent Inference Engine Enables 252× More Hyperparameter Candidates
**Source:** [alphaXiv — Nov 4, 2026](https://www.alphaxiv.org/) · [Emergent Mind](https://www.emergentmind.com/topics/conversation-compression-strategies)

A paper submitted to alphaXiv (November 4) describes a **persistent inference engine from Together AI** that keeps hot KV-cache state across optimization agent iterations. By eliminating repeated prefill cost for shared prompt prefixes, it allows optimization agents to evaluate 252 times more hyperparameter candidates within the same wall-clock budget.

**Why it matters:** Hyperparameter search and architecture search are inner-loop computations where inference speed directly multiplies the quality of results. A 252× candidate throughput increase means meta-learning and AutoML workloads that were previously compute-prohibitive become practical on commodity Together AI endpoints.
